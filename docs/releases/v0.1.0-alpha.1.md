# ARKlinux 0.1.0-alpha.1 — First Bare-Metal Boot

Status: Alpha / Developer Preview

This milestone records the first ARKlinux image proven to boot as its own operating system in both QEMU and on the HP Z4 G4 workstation from a SanDisk Cruzer Glide USB.

## Proven in this milestone

- UEFI boot from the ARKlinux EFI system partition.
- Direct boot of the `arklinux-kernel` artifact.
- `initramfs-arklinux.img` startup.
- ARKROOT Btrfs root filesystem.
- 48 defined Btrfs subvolumes spanning the OS, A.R.K. process/state domains, and reserved Aletheia persistence domains.
- systemd startup and operator login.
- Native A.R.K. process/service framework and role separation.
- QEMU boot proof.
- HP Z4 G4 bare-metal USB boot proof.
- Wayland/Labwc graphical foundation on the physical workstation.

## Architecture represented

ARKlinux is the operating-system substrate. A.R.K. is the coordinated collection of native processes and supporting pathways running within that substrate; it is not a single application or daemon.

The current process framework includes core coordination/bus/watchdog functions together with lifecycle, cognition, correspondence, effect, intake, model-routing, and hardware/I-O process groups.

The filesystem also reserves the persistent boundaries required for the later Aletheia layer so the base storage architecture does not need to be redesigned when developmental memory and identity are added.

## Not complete in this release

This release does not claim a finished ARKlinux desktop. The current Labwc/Wayland interface is a graphical infrastructure proof and temporary desktop scaffold.

Aletheia developmental persistence, DREAMER/ID, and Cube developmental/instinctive behavior are not claimed complete in this release.

The current image should not be treated as production-ready or security-hardened for deployment on untrusted networks.

## Boot image

The validated development artifact is a raw GPT disk image named:

`arklinux-x86_64.raw`

The image contains:

- ARKESP — FAT32 EFI system partition.
- ARKROOT — Btrfs root partition.

For GitHub Release distribution, the raw image should be compressed with zstd and split into parts smaller than GitHub's per-asset size limit. Publish a SHA-256 manifest for both the compressed parts and the reconstructed raw image.

## Intended release assets

- `SHA256SUMS`
- `arklinux-x86_64.raw.sha256`
- `arklinux-x86_64.raw.zst.part-00`
- additional sequential `arklinux-x86_64.raw.zst.part-*` files as required

## Reconstruction

After downloading all image parts into one directory:

```bash
sha256sum -c SHA256SUMS
cat arklinux-x86_64.raw.zst.part-* > arklinux-x86_64.raw.zst
zstd -d arklinux-x86_64.raw.zst
sha256sum -c arklinux-x86_64.raw.sha256
```

The resulting `arklinux-x86_64.raw` can be written to a sufficiently large disposable block device. Writing a raw disk image destroys the existing contents of the target device.

## Release significance

`v0.1.0-alpha.1` marks the transition from ARKlinux as a source/design system to an independently bootable OS image demonstrated on both virtual and physical hardware.
